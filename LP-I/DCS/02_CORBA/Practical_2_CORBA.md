# Practical 2: Calculator Using CORBA

## Aim

To develop a distributed calculator using CORBA and demonstrate object
brokering between a client and a server.

## Theory

CORBA stands for **Common Object Request Broker Architecture**. It allows
objects in different processes, and potentially written in different
programming languages, to call one another. The **Object Request Broker (ORB)**
routes a client's method request to the remote object and returns the result.

The program uses **IDL** (Interface Definition Language) to describe the
calculator operations independently of Java. The `idlj` compiler reads
`Calculator.idl` and generates Java interfaces and helper classes, including
`Calculator`, `CalculatorPOA`, and `CalculatorHelper`. These generated files
form the client/server communication layer and should not be edited by hand.

The server's `CalculatorImpl` is the CORBA **servant**: it implements the
operations described by the generated `CalculatorPOA` skeleton. A **POA**
(Portable Object Adapter) connects the servant to the ORB. The server registers
the object reference with the **Naming Service** under the name `Calculator`.
The client resolves this name, obtains a reference using the generated helper,
and invokes the arithmetic method through that reference. The ORB carries the
request and result between the two programs.

This Java example uses the CORBA APIs (`org.omg.CORBA`) and the `idlj` and
`orbd` tools. It is easiest to run with JDK 8, which includes them; Java removed
its bundled CORBA APIs and tools starting with JDK 11. See [Oracle's JDK
migration guide](https://docs.oracle.com/en/java/javase/22/migrate/removed-tools-and-components.html)
and [JDK 8 tool list](https://docs.oracle.com/javase/8/docs/technotes/tools/).

## Files and roles

| File | Role |
|---|---|
| `Calculator.idl` | Declares the remote calculator interface. |
| `CalculatorServer.java` | Implements the operations and registers the servant. |
| `CalculatorClient.java` | Finds the service and asks which operation to call. |
| `CalcModule/` | Generated by `idlj`; contains the Java mapping of the IDL. |

## Program

### `Calculator.idl`

```idl
module CalcModule {
    interface Calculator {
        double add(in double a, in double b);
        double subtract(in double a, in double b);
        double multiply(in double a, in double b);
        double divide(in double a, in double b);
    };
};
```
| Line(s) | Explanation |
|---|---|
| 1 | Opens the IDL module `CalcModule`; generated Java files use this as their package. |
| 2 | Declares the remote interface named `Calculator`. |
| 3 | Declares the remote addition operation; `in` marks both values as inputs. |
| 4 | Declares subtraction with two input values. |
| 5 | Declares multiplication with two input values. |
| 6 | Declares division with two input values. |
| 7 | Closes the interface. |
| 8 | Closes the module. |

### `CalculatorServer.java`

```java
import CalcModule.*;
import org.omg.CORBA.ORB;
import org.omg.CORBA.BAD_PARAM;
import org.omg.PortableServer.POA;
import org.omg.PortableServer.POAHelper;
import org.omg.CosNaming.NamingContextExt;
import org.omg.CosNaming.NamingContextExtHelper;
import org.omg.CosNaming.NameComponent;

public class CalculatorServer {

    static class CalculatorImpl extends CalculatorPOA {
        public double add(double a, double b) {
            return a + b;
        }

        public double subtract(double a, double b) {
            return a - b;
        }

        public double multiply(double a, double b) {
            return a * b;
        }

        public double divide(double a, double b) {
            if (b == 0) {
                throw new BAD_PARAM("Division by zero");
            }
            return a / b;
        }
    }

    public static void main(String[] args) {
        try {
            ORB orb = ORB.init(args, null);

            POA rootPOA = POAHelper.narrow(
                    orb.resolve_initial_references("RootPOA"));
            rootPOA.the_POAManager().activate();

            CalculatorImpl servant = new CalculatorImpl();
            org.omg.CORBA.Object ref = rootPOA.servant_to_reference(servant);
            Calculator calculator = CalculatorHelper.narrow(ref);

            org.omg.CORBA.Object nameService =
                    orb.resolve_initial_references("NameService");
            NamingContextExt namingContext =
                    NamingContextExtHelper.narrow(nameService);

            NameComponent[] path = namingContext.to_name("Calculator");
            namingContext.rebind(path, calculator);

            System.out.println("CORBA Calculator Server is ready.");
            orb.run();
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
```
| Line(s) | Explanation |
|---|---|
| 1 | Imports the generated calculator interface, POA skeleton, and helper classes. |
| 2-3 | Import the ORB and CORBA's `BAD_PARAM` exception, used here for division by zero. |
| 4-5 | Import the Portable Object Adapter and its helper. |
| 6-8 | Import Naming Service types used to register the calculator by name. |
| 10 | Declares the server class. |
| 12 | Declares the servant implementation and extends the generated POA skeleton. |
| 13-15 | Implement addition by returning the sum. |
| 17-19 | Implement subtraction by returning the difference. |
| 21-23 | Implement multiplication by returning the product. |
| 25 | Begins the division operation. |
| 26-28 | Checks for a zero divisor and raises `BAD_PARAM` if division is invalid. |
| 29 | Returns the quotient when the divisor is nonzero. |
| 31 | Closes the servant implementation class. |
| 33 | Begins the server's `main` method. |
| 34 | Starts exception handling for server setup. |
| 35 | Initializes the ORB using any command-line ORB options. |
| 37-38 | Resolves the ORB's `RootPOA` reference and narrows it to the POA type. |
| 39 | Activates the POA manager so the POA can dispatch requests to servants. |
| 41 | Creates the calculator servant. |
| 42 | Converts the servant into a CORBA object reference. |
| 43 | Narrows that reference to the generated `Calculator` type. |
| 45-46 | Resolves the Naming Service reference from the ORB. |
| 47-48 | Narrows the general CORBA reference to a naming context. |
| 50 | Converts the string name `Calculator` to a CORBA name path. |
| 51 | Registers or replaces the calculator reference under that name. |
| 53 | Prints a message that server setup has completed. |
| 54 | Keeps the ORB running so it can receive client requests. |
| 55-57 | Catches startup errors and prints their details. |
| 58-59 | Close the `main` method and server class. |

### `CalculatorClient.java`

```java
import CalcModule.*;
import org.omg.CORBA.ORB;
import org.omg.CosNaming.NamingContextExt;
import org.omg.CosNaming.NamingContextExtHelper;
import java.util.Scanner;

public class CalculatorClient {
    public static void main(String[] args) {
        try {
            ORB orb = ORB.init(args, null);

            org.omg.CORBA.Object nameService =
                    orb.resolve_initial_references("NameService");
            NamingContextExt namingContext =
                    NamingContextExtHelper.narrow(nameService);

            Calculator calculator = CalculatorHelper.narrow(
                    namingContext.resolve_str("Calculator"));

            Scanner input = new Scanner(System.in);
            System.out.print("Enter first number: ");
            double a = input.nextDouble();
            System.out.print("Enter second number: ");
            double b = input.nextDouble();

            System.out.println("1. Addition");
            System.out.println("2. Subtraction");
            System.out.println("3. Multiplication");
            System.out.println("4. Division");
            System.out.print("Enter choice: ");
            int choice = input.nextInt();

            double result;
            switch (choice) {
                case 1:
                    result = calculator.add(a, b);
                    break;
                case 2:
                    result = calculator.subtract(a, b);
                    break;
                case 3:
                    result = calculator.multiply(a, b);
                    break;
                case 4:
                    result = calculator.divide(a, b);
                    break;
                default:
                    System.out.println("Invalid choice.");
                    input.close();
                    return;
            }

            System.out.println("Result = " + result);
            input.close();
        } catch (Exception e) {
            System.err.println("Client error: " + e);
        }
    }
}
```
| Line(s) | Explanation |
|---|---|
| 1 | Imports the generated calculator interface and helper classes. |
| 2 | Imports the ORB type. |
| 3-4 | Import naming-context types for finding the remote object. |
| 5 | Imports `Scanner` for keyboard input. |
| 7 | Declares the client class. |
| 8 | Begins the client's `main` method. |
| 9 | Starts a `try` block for ORB access, lookup, and remote calls. |
| 10 | Initializes the client's ORB using supplied ORB options. |
| 12-13 | Resolves the Naming Service reference. |
| 14-15 | Narrows that reference to the naming-context type. |
| 17-18 | Finds the name `Calculator` and narrows the result to the calculator interface. |
| 20 | Creates a scanner to read keyboard input. |
| 21-22 | Prompts for and reads the first number. |
| 23-24 | Prompts for and reads the second number. |
| 26-30 | Displays the operation menu and asks for a choice. |
| 31 | Reads the selected menu number. |
| 33 | Declares a variable to hold the result. |
| 34 | Starts a `switch` to select the requested operation. |
| 35-37 | Calls the remote addition method and exits this case with `break`. |
| 38-40 | Calls the remote subtraction method and exits this case. |
| 41-43 | Calls the remote multiplication method and exits this case. |
| 44-46 | Calls the remote division method and exits this case. |
| 47-50 | Handles an invalid menu choice, closes the scanner, and returns from `main`. |
| 51 | Closes the `switch`. |
| 53 | Displays the result returned by the remote operation. |
| 54 | Closes the input scanner. |
| 55-57 | Catches client-side errors, including lookup and remote-call failures. |
| 58-59 | Close the `main` method and client class. |

## How to compile and run

These commands require JDK 8 because JDK 11 and later do not include the Java
CORBA APIs or the `idlj` and `orbd` tools.

Open three terminals in this folder. Make sure `java`, `javac`, `idlj`, and
`orbd` resolve to the JDK 8 `bin` directory.

Generate Java source from the IDL once:

```powershell
idlj -fall Calculator.idl
```

This creates the `CalcModule` directory containing generated Java source.

Compile the client, server, and referenced generated source:

```powershell
javac CalculatorServer.java CalculatorClient.java
```

Start the CORBA Naming Service in terminal 1:

```powershell
orbd -ORBInitialPort 1050
```

Start the server in terminal 2:

```powershell
java CalculatorServer -ORBInitialPort 1050
```

Wait for `CORBA Calculator Server is ready.` Start the client in terminal 3:

```powershell
java CalculatorClient -ORBInitialPort 1050
```

Enter two numbers and an operation choice. For example, entering `8`, `2`, and
choice `4` should display `Result = 4.0`. Keep the naming service and server
running while using the client. Stop each process with Ctrl+C when finished.

## Execution flow to remember

1. Write the remote contract in IDL.
2. Run `idlj` to generate the Java interface, POA skeleton, and helpers.
3. Implement the generated POA class in the server.
4. Start the Naming Service and register the servant as `Calculator`.
5. Have the client resolve `Calculator` and call one of its remote methods.

## Viva questions and short answers

1. **What does CORBA stand for?**  
   Common Object Request Broker Architecture.

2. **What is the role of an ORB?**  
   It routes remote object requests from the client to the server and returns
   results to the client.

3. **What is IDL?**  
   Interface Definition Language; it describes remote operations independently
   of a particular programming language.

4. **What does `idlj` do?**  
   It generates Java interfaces, skeletons, and helper classes from an IDL file.

5. **What is a servant?**  
   The server-side object that implements the CORBA operations; here it is
   `CalculatorImpl`.

6. **What is a POA?**  
   The Portable Object Adapter connects a servant to the ORB and manages how it
   receives requests.

7. **What is the purpose of the Naming Service?**  
   It lets the client find an object reference using a readable name such as
   `Calculator`.

8. **Why does the server call `orb.run()`?**  
   It keeps the server ORB active so it can process incoming client requests.

9. **How is division by zero handled here?**  
   The server checks whether the second value is zero and raises CORBA's
   `BAD_PARAM` exception.

10. **Why does this code need an older JDK?**  
    It uses Java CORBA APIs and tools that were removed from the JDK starting
    with JDK 11.
