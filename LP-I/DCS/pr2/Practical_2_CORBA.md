# Practical 2: Calculator Using CORBA

## Aim

To develop a distributed calculator using CORBA and demonstrate object
brokering between a client and a server.

## Theory

CORBA stands for Common Object Request Broker Architecture. It allows objects
in separate processes, and potentially written in different programming
languages, to communicate. The ORB (Object Request Broker) carries a client's
request to the server object and returns the result.

IDL (Interface Definition Language) describes the remote operations. The idlj
tool generates Java interface and helper classes from the IDL. The server
implements the generated skeleton, registers its object with the Naming
Service, and waits for calls. The client looks up the registered object and
calls an operation through the ORB.

The calculator supports addition, subtraction, multiplication, and division.
The four server methods follow the same simple pattern: receive two numbers
and return the result. The division method also checks for division by zero.

## Files and roles

| File | Role |
|---|---|
| Calculator.idl | Declares the remote calculator operations. |
| CalculatorServer.java | Implements the operations and registers the servant. |
| CalculatorClient.java | Finds the calculator, reads input, and calls the selected operation. |
| CalcModule/ | Generated by idlj; contains Java interfaces, skeletons, and helper classes. |

## Program and explanation

### Calculator.idl

~~~idl
module CalcModule {
    interface Calculator {
        double add(in double a, in double b);
        double subtract(in double a, in double b);
        double multiply(in double a, in double b);
        double divide(in double a, in double b);
    };
};
~~~

**Explanation:** module CalcModule groups the IDL interface. The idlj tool
uses this module name when generating Java files. interface Calculator
declares the remote service.

Each operation returns a double and accepts two double inputs. The word in
means that a and b are sent into the operation. The four operations describe
what the client is allowed to ask the remote calculator to do. The braces and
semicolons close the interface and module declarations.

### CalculatorServer.java

~~~java
import CalcModule.*;
import org.omg.CORBA.ORB;
import org.omg.CORBA.BAD_PARAM;
import org.omg.PortableServer.*;
import org.omg.CosNaming.*;
~~~

**Explanation:** These lines import generated calculator types and CORBA
classes. ORB provides the Object Request Broker. BAD_PARAM is used when
division by zero is requested. PortableServer provides POA classes.
CosNaming provides Naming Service classes. The * imports the classes in a
package.

~~~java
public class CalculatorServer {
    static class CalculatorImpl extends CalculatorPOA {
~~~

**Explanation:** Declares the server class and an inner class named
CalculatorImpl. CalculatorImpl is the servant: the server-side object that
performs the operations. CalculatorPOA is the skeleton generated from the IDL.
Extending it connects this implementation to the generated CORBA interface.

~~~java
        public double add(double a, double b) {
            return a + b;
        }

        public double subtract(double a, double b) {
            return a - b;
        }

        public double multiply(double a, double b) {
            return a * b;
        }
~~~

**Explanation:** These methods implement the first three IDL operations.
Each receives a and b and returns the matching arithmetic result. The method
names and parameter types must match the generated interface. Remember the
pattern: add uses +, subtract uses -, multiply uses *.

~~~java
        public double divide(double a, double b) {
            if (b == 0) {
                throw new BAD_PARAM("Division by zero");
            }
            return a / b;
        }
    }
}
~~~

**Explanation:** Implements division. The if statement checks whether the
second number is zero. If it is, the method raises BAD_PARAM instead of
dividing by zero. Otherwise, it returns a divided by b. The closing braces end
the divide method, CalculatorImpl, and CalculatorServer class.

~~~java
    public static void main(String[] args) {
        try {
            ORB orb = ORB.init(args, null);
~~~

**Explanation:** main is where the server program starts. static means Java
can run it without first creating a CalculatorServer object. args can contain
ORB command-line options. The try block allows setup errors to be handled.
ORB.init creates the server's Object Request Broker.

~~~java
            POA rootPOA = POAHelper.narrow(
                    orb.resolve_initial_references("RootPOA"));
            rootPOA.the_POAManager().activate();
~~~

**Explanation:** The ORB finds the RootPOA, the standard adapter that connects
a servant to the ORB. resolve_initial_references returns a general CORBA
reference. POAHelper.narrow converts it to the POA type. Activating the POA
manager allows it to dispatch requests to servants.

~~~java
            Calculator calculator = CalculatorHelper.narrow(
                    rootPOA.servant_to_reference(new CalculatorImpl()));
~~~

**Explanation:** new CalculatorImpl() creates the servant. servant_to_reference
asks the POA for a CORBA object reference to it. CalculatorHelper.narrow
converts that general reference to the generated Calculator type. The variable
calculator holds the resulting CORBA reference.

~~~java
            NamingContextExt naming = NamingContextExtHelper.narrow(
                    orb.resolve_initial_references("NameService"));
            naming.rebind(naming.to_name("Calculator"), calculator);
~~~

**Explanation:** The ORB finds the Naming Service, and the helper narrows its
general reference to a NamingContextExt reference. to_name converts the
readable name Calculator into the CORBA name format. rebind registers the
calculator reference using that name, replacing an old binding if present.

~~~java
            System.out.println("CORBA Calculator Server is ready.");
            orb.run();
~~~

**Explanation:** Prints a ready message. orb.run keeps the server ORB active
to receive client requests. Leave the server process running while using the
client.

~~~java
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
~~~

**Explanation:** Handles setup errors and prints their details. The braces
close the catch block, main method, and server class.

### CalculatorClient.java

~~~java
import CalcModule.*;
import org.omg.CORBA.ORB;
import org.omg.CosNaming.*;
import java.util.Scanner;
~~~

**Explanation:** Imports the generated calculator types, the ORB, Naming
Service classes, and Scanner. Scanner reads numbers and the menu choice typed
by the user.

~~~java
public class CalculatorClient {
    public static void main(String[] args) {
        try {
            ORB orb = ORB.init(args, null);
~~~

**Explanation:** Declares the client class and its main starting method. The
try block catches errors that may occur during setup or remote calls.
ORB.init creates the client's ORB and passes it any command-line options.

~~~java
            NamingContextExt naming = NamingContextExtHelper.narrow(
                    orb.resolve_initial_references("NameService"));
            Calculator calculator = CalculatorHelper.narrow(
                    naming.resolve_str("Calculator"));
~~~

**Explanation:** First the client finds the Naming Service and narrows it to
NamingContextExt. Then resolve_str asks for the object registered as
Calculator. CalculatorHelper.narrow converts the general CORBA reference to
the generated Calculator type. The calculator variable is now the remote
reference used to call the server.

~~~java
            Scanner input = new Scanner(System.in);
            System.out.print("Enter first number: ");
            double a = input.nextDouble();
            System.out.print("Enter second number: ");
            double b = input.nextDouble();
~~~

**Explanation:** Creates a Scanner for keyboard input. The prompts ask for two
numbers. nextDouble reads each value and stores them in a and b.

~~~java
            System.out.println("1. Addition");
            System.out.println("2. Subtraction");
            System.out.println("3. Multiplication");
            System.out.println("4. Division");
            System.out.print("Enter choice: ");
            int choice = input.nextInt();
~~~

**Explanation:** Displays the four operations and asks the user to select one.
nextInt reads the selection and stores it in choice.

~~~java
            double result;
            switch (choice) {
~~~

**Explanation:** Declares result to hold the answer. switch checks the value
of choice and runs the matching case below.

~~~java
                case 1:
                    result = calculator.add(a, b);
                    break;
                case 2:
                    result = calculator.subtract(a, b);
                    break;
                case 3:
                    result = calculator.multiply(a, b);
                    break;
                case 4:
                    result = calculator.divide(a, b);
                    break;
~~~

**Explanation:** Each case makes a remote call to the corresponding server
method and saves its returned value in result. break exits the switch so the
next case does not run as well.

~~~java
                default:
                    System.out.println("Invalid choice.");
                    input.close();
                    return;
            }
~~~

**Explanation:** default runs if the user enters anything other than 1, 2, 3,
or 4. It prints an error, closes the Scanner, and return exits main. The last
brace closes the switch.

~~~java
            System.out.println("Result = " + result);
            input.close();
~~~

**Explanation:** Prints the answer returned by the server and closes the
Scanner.

~~~java
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
}
~~~

**Explanation:** Catches errors such as a failed Naming Service lookup or
remote call, then prints details. The braces close the catch block, main
method, and client class.

## How to compile and run

**JDK requirement:** This code uses Java CORBA packages and the idlj and orbd
tools bundled with JDK 8. They were removed from the JDK starting with JDK 11.
The setup previously checked for this practical uses JDK 17, so it cannot run
this code as-is without a compatible CORBA setup.

With JDK 8 configured, open three terminals in this folder. First generate the
Java files from the IDL:

```powershell
$env:PATH = 'C:\Program Files\Eclipse Adoptium\jdk-8.0.512.9-hotspot\bin;' + $env:PATH
```

~~~powershell
idlj -fall Calculator.idl
~~~

This creates the CalcModule folder. Do not edit generated files manually.

Compile the server and client:

~~~powershell
javac CalculatorServer.java CalculatorClient.java
~~~

In terminal 1, start the CORBA Naming Service:

~~~powershell
orbd -ORBInitialPort 1050
~~~

In terminal 2, start the server with the same naming-service port:

~~~powershell
java CalculatorServer -ORBInitialPort 1050
~~~

Wait for the ready message. In terminal 3, start the client:

~~~powershell
java CalculatorClient -ORBInitialPort 1050
~~~

Enter two numbers and a choice from 1 to 4. For example, entering 8, 2, and
choice 4 should display Result = 4.0. Keep the Naming Service and server
running while using the client. Stop each process with Ctrl+C.

## Execution flow to remember

1. Describe the four calculator operations in IDL.
2. Run idlj to generate Java types and the server skeleton.
3. Implement the generated skeleton in CalculatorImpl.
4. Connect the servant to the ORB through the POA.
5. Register the servant with the Naming Service as Calculator.
6. The client looks up Calculator and calls the selected remote method.

## Viva questions and short answers

1. **What does CORBA stand for?**  
   Common Object Request Broker Architecture.

2. **What does the ORB do?**  
   It carries remote method requests from the client to the server and returns
   the results.

3. **What is IDL?**  
   Interface Definition Language; it describes remote operations independently
   of Java.

4. **What does idlj do?**  
   It generates Java interfaces, skeletons, and helper classes from IDL.

5. **What is a servant?**  
   The server-side object implementing the CORBA operations; here it is
   CalculatorImpl.

6. **What is a POA?**  
   The Portable Object Adapter connects a servant to the ORB and helps it
   receive requests.

7. **What does the Naming Service do?**  
   It lets clients find an object by a readable name such as Calculator.

8. **Why does the server call orb.run()?**  
   To keep the ORB active and ready to process client requests.

9. **How is division by zero handled?**  
   The server raises BAD_PARAM if the second value is zero.

10. **Why does this code need a compatible older JDK?**  
    It uses Java CORBA APIs and tools that were removed from the JDK starting
    with JDK 11.
